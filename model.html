architecture

Two inputs to the point decoder.

The decoder reads a local source feature through Q and the full clip through K/V. Both paths are present in the old multiview model and in R00.

PathWhat is passedWhere it enters
Local sourceBilinear sample from the frozen DINO patch grid of image (t_src, v_src), before Omega processing.Linear source adapter, summed with UV Fourier features, three relative-time embeddings and two view embeddings; then LayerNorm. ↗
Clip evidenceFinal output after Omega pair 23: every patch, native camera/register token, and scene token.Observed-role and relative capture-time embeddings are added; each of the eight blocks computes its own K/V projections. ↗
OutputOne five-channel prediction per query.XYZ in camera (t_cam, v_cam) at target time t_tgt, plus confidence and visibility logits.

A0 uses no intermediate-layer fusion, contextual source residual, routed attention or tail isolation.

Token budget per clip

DatasetPatch grid / imagePacked K/V rowsTraining queries
InternData30 × 40 = 1,20016 × 3 × (1,200 + 17) + 64 = 58,4804,096
LIBERO32 × 32 = 1,02416 × 3 × (1,024 + 17) + 64 = 50,0324,096

The 17 native rows are one camera token and 16 registers per image. The 64 scene tokens belong to the whole clip. Full perception runs all 24 Omega pairs; it does not use the streaming fast-pair schedule or historical memory.

Objective used by both matched baselines

L = mean[c · meanxyz|slog(p / dp) − slog(g / dg)| − 0.2 log(c) + 0.1 BCE(v, v*)]

Each clip has separate predicted and ground-truth mean absolute depth normalizers, dp and dg. The predicted normalizer remains differentiable. Geometry includes occluded valid queries. R00 adds no ray penalty, UV loss, displacement loss or normal loss.

Equal clip exposure to the two datasets does not mean their losses are computed together. Every optimizer update uses one dataset family; the balanced exposure is achieved over the 15-update schedule.

evaluation

The old branch has a three-view evaluator.

evaluate_quarc_multiview.py ↗ feeds all three agent RGB streams to QuARC. A point is selected in one source camera at the first frame and queried at every target frame into all three target cameras. Each clip is evaluated independently, with one full-perception forward call. ↗

Protocol itemExact behavior
CohortReuses a frozen 20-clip cohort: 10 train + 10 test, distinct scenes within each split. It is a diagnostic sample, not a full-dataset benchmark.
Window16 frames at stride 2. Source time resets to the first frame of each clip; no cross-clip state.
Point setAll stored points visible and in bounds in the chosen source camera at t0, valid throughout the clip. Point count varies. “Dense” means dense over the stored point set, not every image pixel.
Query layout[target time, point ID, target camera]. For N points, 16 × N × 3 queries. t_cam follows the target camera’s capture time at t_tgt.
View casesOne same-view output and two cross-view outputs per point/time. Source camera rotates across the frozen cohort.
Visualization24 points for display, nominally 12 static + 12 moving with image-space coverage. Metric scoring uses the full retained point set. Display motion threshold: maximum excursion > 1 mm.
AggregationQuery-count-weighted sums and counts; separate train/test and same-view/cross-view summaries. Pairwise disagreement pools all three target-view pairs.

Metrics and scale

MetricComputationInterpretation
Pixel EPE (px)Project raw predicted and GT target-camera XYZ using K; mean 2D Euclidean error. Keep GT-visible rows whose predicted projection is finite and has positive depth.Scalar scale cancels under projection. Invalid predictions are excluded, so coverage must be reported alongside this error.
Aligned XYZ EPE (m)α = mean|GT z| / max(mean|pred z|, 10⁻⁶), shared over all points, times and views of a clip. Transform α·pred through GT camera poses; undo episode scale and center. Score every retained point/time.GT-assisted scale alignment. It is a metric-unit error after alignment, not evidence that the model recovered absolute scale independently.
Cross-view world disagreement (m)After the same shared alignment, compare each pair of the three world-coordinate predictions for the same point and time.Measures cross-view consistency. Mutually consistent predictions may still be wrong.
D4RT component lossesReconstruct confidence-weighted signed-log XYZ, −0.2 log(confidence), and 0.1 visibility BCE from saved predictions.Diagnostic loss curves; they are separate from the geometric evaluation metrics.

The restoration is world = [R_wc · (α · pred) + t_wc_normalized] · episode_scale + episode_center. A single α is shared by all target views. Camera transforms and episode normalization come from ground truth. ↗

migration

Portable, with a small evaluation adapter.

The query contract and five-output decoder are compatible. Reuse the query, scoring and rendering functions; adapt the launcher to B300’s checkpoint and data layout.

PartRequired adaptation
Model and configLoad the campaign’s archived model.yaml and A0 config.json. Preserve the matching runtime; do not take today’s modified working tree as the checkpoint definition.
CheckpointOld code reads trainer_state.optimizer_step and catalog-versions/node-0/*/config.yaml. Campaign checkpoints store step and signature. Keep strict model state loading.
Dataset / frozen inputsRemap old request URIs to B300 H5 files and verify sample identity and digest. Recover protocol.json, per-clip metadata, queries.npz and video.npz, or explicitly build a new frozen cohort.
Reader and transformsAdapt full_dataset(cfg) to the current helper, retain center/scale for reconstruction, and broadcast constant K matrices to the evaluator’s per-frame layout.
Preparation dependenciesThe original cohort preparation imports train.full_d4rt and an OpenD4RT checkout. Those are unnecessary for the five-output evaluator; replace preparation with v6 geometry/query construction, or reuse the archived cohort.
Projection failuresRetain the historical EPE for reproducibility, but also report invalid-projection rate and an all-query penalized score. Do not silently change the old metric under the same name.
Before reporting resultsVerify query IDs, projection/pose consistency, normalization and checkpoint identity; then run the same frozen queries on both models.

Validation completed here: four CPU scoring checks (scale, cross-view error, invalid projections and loss), plus the old query/metric fixture against B300’s current query helpers. Model inference and end-to-end migration have not been run.
